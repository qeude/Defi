# Native link focus comparison

Inspected current default-branch source on 2026-09-05; this is source analysis, not a desktop reliability benchmark. No Defi code or desktop state changed.

Pinned snapshots: OmniWM `dc09c91f184b039c380abf61ab95641eb77f319e`; Paneru `2d1cc8880ca6b470f8e68bce3027dd859c4fb113`.

## OmniWM

- Native app activation enters through NSWorkspace.didActivateApplicationNotification, is normalized to appActivated, then handleAppActivation. AX focused-window notifications enter the same handler with a distinct source. There is also a CGS frontmost-app changed source. These are application/window focus observations, not URL-opening notifications. Sources: [Sources/OmniWM/Core/Controller/ServiceLifecycleManager.swift:739](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/ServiceLifecycleManager.swift#L739), [Sources/OmniWM/Core/Intake/EventInterpreter.swift:34](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Intake/EventInterpreter.swift#L34), [Sources/OmniWM/Core/Intake/EventInterpreter.swift:74](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Intake/EventInterpreter.swift#L74), [Sources/OmniWM/Core/Controller/AXEventHandler.swift:477](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L477).
- Ordinary external activation does not require a recent human click. On conflicting native app activation it clears a pending managed focus request and records provisional external PID focus before asynchronous fact resolution. This is a deliberate relinquishing of the old focus request. It suppresses focus-follows-mouse for 0.4 seconds during a native app switch. [Sources/OmniWM/Core/Controller/AXEventHandler.swift:1595](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L1595) (especially 1651–1706).
- Resolved facts must match the latest observation generation, app-visibility generation, callback generation, and must not precede a newer issued focus intent. [Sources/OmniWM/Core/Controller/AXEventHandler.swift:1718](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L1718) (1720–1754).
- Background AX focus notifications are treated differently from application activation: suppress when latest native activation agrees with current frontmost application but this AX observation represents another app, unless a matching managed request/mouse intent grants authority. Recent mouse intent is therefore an exception for conflicting AX observations, not a global prerequisite for external app activation. [Sources/OmniWM/Core/Controller/AXEventHandler%2BFocusObservation.swift:7](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler%2BFocusObservation.swift#L7) (7–60, 96–116).
- Own focus observations are classified as active echo, late echo (retired within one second), or external. An external authoritative AX observation can override a pending request; recognized echoes cannot. [Sources/OmniWM/Core/Intent/IntentLedger.swift:245](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Intent/IntentLedger.swift#L245), [Sources/OmniWM/Core/Intent/IntentLedger.swift:847](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Intent/IntentLedger.swift#L847), [Sources/OmniWM/Core/Controller/AXEventHandler.swift:3847](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L3847). Note the term authoritative is specifically AX focusedWindowChanged in this code, not NSWorkspace activation: [Sources/OmniWM/Core/Controller/ServiceLifecycleManager.swift:7](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/ServiceLifecycleManager.swift#L7).
- Once accepted, an inactive managed window's owning workspace is activated via confirmManagedFocus(activateWorkspaceOnMonitor: shouldActivateWorkspace), its Niri viewport is adjusted without another AX focus operation, and an appActivationTransition is committed. This is its own workspace transition. Native macOS Space changes are observed via a separate intake case. [Sources/OmniWM/Core/Controller/AXEventHandler.swift:2265](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L2265) (2265–2324, 2390–2442), [Sources/OmniWM/Core/Intake/EventInterpreter.swift:30](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Intake/EventInterpreter.swift#L30).
- Missing focused-window data does not unconditionally cause blind focus retries: the handler continues existing managed requests in retry context, rescans selected same-app windows, or retains PID-only external focus. Avoid describing it as a universal polling guarantee. [Sources/OmniWM/Core/Controller/AXEventHandler.swift:3747](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Sources/OmniWM/Core/Controller/AXEventHandler.swift#L3747).
- First-party tests cover newer observations defeating stale facts, stale retries, and background AX focus authority, but do not establish 100% URL-opening success. [Tests/OmniWMTests/ManagedFocusAdmissionTests.swift:126](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Tests/OmniWMTests/ManagedFocusAdmissionTests.swift#L126), [Tests/OmniWMTests/ManagedFocusAdmissionTests.swift:173](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Tests/OmniWMTests/ManagedFocusAdmissionTests.swift#L173), [Tests/OmniWMTests/ManagedFocusAdmissionTests.swift:705](https://github.com/BarutSRB/OmniWM/blob/dc09c91f184b039c380abf61ab95641eb77f319e/Tests/OmniWMTests/ManagedFocusAdmissionTests.swift#L705).

## Paneru

- Paneru's internal focus path uses Carbon application FrontSwitched events, normalized to ApplicationFrontSwitched; its NSWorkspace ApplicationActivated event explicitly exists for subscribers instead. [src/platform/process.rs:327](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/platform/process.rs#L327), [src/platform/process.rs:429](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/platform/process.rs#L429), [src/events.rs:71](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/events.rs#L71).
- FrontSwitched immediately queries the app's AX focused window and synthesizes WindowFocused. If that query errors, it retries for up to two seconds. The retry rechecks app.is_frontmost(), discards stale work when the app loses frontmost status, and emits WindowFocused once AX succeeds. This two-second deadline is an AX-read retry duration; it is not a maximum permitted age of a user click. [src/ecs/triggers.rs:86](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/triggers.rs#L86), [src/ecs/systems.rs:517](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/systems.rs#L517).
- AX focused-window and focused-UI-element notifications independently feed WindowFocused. [src/manager/app.rs:404](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/manager/app.rs#L404).
- WindowFocused rejects events when the app is no longer frontmost, or when a successful fresh AX focused-window query names a different window. A failed fresh query does not itself reject. It reactivates the owning virtual strip before treating already-focused events as duplicates. Unknown windows get a two-second StrayFocusEvent retry. No recent-click requirement exists in this handler. [src/ecs/triggers.rs:207](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/triggers.rs#L207) (especially 216–228, 246–263, 275–310).
- Own restore-focus echoes have a RestoreFocusMarker that absorbs duplicate acknowledgments and prevents viewport reshuffling. It persists on matching events and is removed when focus moves elsewhere. Ordinary duplicate focus may intentionally reshuffle to restore visibility. [src/ecs/triggers.rs:318](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/triggers.rs#L318).
- Activating the strip causes show_active_workspace to park other virtual strips and restore the target strip. The code explicitly distinguishes these virtual strips from the physical workspace/Space they belong to; this is not a native Space-switch command. [src/ecs/workspace.rs:1095](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/workspace.rs#L1095) (1095–1168); setup precreates virtual workspaces per physical space: [src/ecs/systems.rs:137](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/ecs/systems.rs#L137).
- First-party tests cover stale focus rejection and repeated external focus restoring an already-focused window's viewport; no 100% reliability claim follows. [src/tests/interaction.rs:560](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/tests/interaction.rs#L560), [src/tests/interaction.rs:585](https://github.com/karinushka/paneru/blob/2d1cc8880ca6b470f8e68bce3027dd859c4fb113/src/tests/interaction.rs#L585).

## AeroSpace

Pinned snapshot `c548c7f879164c7ab1acde7ecd88f4f19eb53d21`.

- NSWorkspace application activation schedules a cancellable refresh with optimistic workspace layout. AX focused-window and window-created notifications also schedule refresh. Each newly scheduled refresh cancels its predecessor. [GlobalObserver.swift](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/GlobalObserver.swift), [refresh.swift:8](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/layout/refresh.swift#L8), [MacApp.swift:69](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/tree/MacApp.swift#L69).
- Refresh reads the frontmost application's AX focused window, then updates its focus cache before layout. A changed native window calls focusWindow, which selects its owning workspace on its monitor. This path has no recent-click admission gate. Popup windows are excluded and unchanged native window IDs are ignored. [getNativeFocusedWindow.swift](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/getNativeFocusedWindow.swift), [refresh.swift:35](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/layout/refresh.swift#L35), [focusCache.swift:6](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/focusCache.swift#L6), [focus.swift:63](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/focus.swift#L63).
- Commands cancel an outstanding refresh, read native focus, run their mutation, and write native focus only when the logical target changes. Native focus jobs also cancel their predecessor. These are cancellation and change-detection safeguards; they are not proof that an activation originated from a human. [refresh.swift:60](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/layout/refresh.swift#L60), [MacApp.swift:130](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/tree/MacApp.swift#L130).
- Workspace layout hides inactive windows in screen corners. Following focus therefore reveals an AeroSpace workspace rather than issuing a native macOS Space switch. The inspected focus observation path uses NSWorkspace and Accessibility; this does not imply every API elsewhere in AeroSpace is public. [refresh.swift:158](https://github.com/nikitabobko/AeroSpace/blob/c548c7f879164c7ab1acde7ecd88f4f19eb53d21/Sources/AppBundle/layout/refresh.swift#L158).

## Rift

Pinned snapshot `beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1`.

- Carbon front-application changes feed global activation. The reactor asks the application actor to resolve its current AX main window before emitting ApplicationActivated. It explicitly avoids immediately replaying a cached window or choosing an arbitrary window of that process. [process.rs](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/process.rs), [reactor.rs:1246](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/reactor.rs#L1246), [app.rs:1467](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/app.rs#L1467).
- Own activation requests carry Quiet metadata. The application actor retains activation context for one second to recognize its own echoes; Quiet activations skip automatic workspace switching. This is origin tracking, not a requirement for a recent click. [app.rs:1428](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/app.rs#L1428), [reactor.rs:1229](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/reactor.rs#L1229).
- External activation can switch to the resolved window's virtual workspace. Guards suppress switching during a workspace transition, shortly associated manual switching, native fullscreen, lifecycle restoration before new input, unmanageable windows, and configured auto_focus_blacklist applications. A main window belonging to the activated process must exist. [reactor.rs:3848](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/reactor.rs#L3848).
- Rift also observes WindowServer focus. It coalesces notifications for one millisecond, queries key focus, and discards results if another wake arrives during the query. After this source initializes, the main-window tracker treats AX focus events as metadata/cold-start fallback rather than allowing stale AX events to replay focus. [window_notify.rs:295](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/window_notify.rs#L295), [main_window.rs](https://github.com/acsandmann/rift/blob/beeac0e5c7dc5c6ae442bd55964af6c316dcd3b1/src/actor/reactor/main_window.rs).

- Tests cover activation targeting when the same app has windows in multiple virtual workspaces, and lifecycle suppression. They do not establish universal end-to-end URL-opening reliability. ## What this implies for Defi

The inspected paths observe native app/window activation; none identifies a URL-opening event. Their ordinary external activation paths do not require a universal recent-click token. They follow the native focus decision and separately reject obsolete observations or their own focus echoes. This supports arbitrary target applications and multi-window applications through the actual resolved window.

Before the implementation below, Defi accepted an application activation only when its latest focus intent is still the latest input and is at most two seconds old. Runtime admission also required a current keyboard or deferred mouse intent. See [UserInputTracking.swift](../../Sources/DefiMacOS/UserInputTracking.swift) and [FocusSelection.swift](../../Sources/DefiRuntime/FocusSelection.swift). A legitimate delayed activation can therefore fail these conditions. This is a source-based explanation of a possible miss, not a trace-confirmed diagnosis of every reported failure.

The recommended next change is to admit confirmed external native activation independently of a recent-click token, resolve the exact window while the activation remains current, and retain Defi's existing command ordering and own-focus suppression. Do not select an arbitrary window by PID. Preserve explicit empty-workspace selection against unchanged or stale native observations. Recheck generation and current frontmost application after asynchronous reads, and cancel pending resolution when superseded.

Paneru's bounded AX-read retry and AeroSpace's current-native-focus refresh are the simplest public-API patterns to evaluate first. OmniWM offers more detailed stale-observation and echo accounting. Rift's private WindowServer mechanism should not be copied under the current API policy.

Following confirmed native activation can also follow a programmatic activation accepted by macOS. These signals cannot prove a human clicked a link. Avoid promising both universal link-opening success and rejection of every unwanted programmatic activation from the same observations.

Before implementation is considered reliable, correlate Defi traces with real external opens: existing target on an inactive workspace, multiple windows of the same app, slow AX response, keyboard link activation, another user command arriving during resolution, delayed own-focus echoes, and an active empty workspace. This research changed documentation only and did not run third-party code or desktop benchmarks.

## Implementation and verification

Implemented on 2026-09-05 using public NSWorkspace activation and Accessibility focus reads. External app activation no longer requires a recent click. Resolution expires after two seconds, checks the current frontmost process, and cannot consume a newer activation. New focus input invalidates pending resolution; ordinary typing does not. Desktop admission also checks the latest Defi command timestamp. Existing internal-focus suppression retires matching activation echoes so they cannot reappear after suppression expires.

While resolving an activation, AX failures no longer reuse a previous window. The existing bounded snapshot scheduling retries the read. A matching activation is rechecked after the AX read and again on the main thread before admission. Accepted native focus reveals the workspace without requesting native focus again, and can preempt an older command animation.

Validation: `swift build`, `swift test` with 746 passing tests, and `./script/build_and_run.sh --verify` passed. `./script/test_desktop.sh` passed 18 tests with Accessibility available; one test was skipped because it required a second on-screen managed window. Computer Use opened a temporary Finder internet-location file in Helium across virtual workspaces, with two traced admissions reporting `activation=true accepted=true mouseIntent=false keyboardIntent=false`. The empty trailing workspace remained selected after waiting, and a matching internal activation reported `reason=internal-focus-echo`. Test tabs and the temporary Finder window were closed. The initial dev workspace and Codex selection were restored, the installed code-signing requirement was unchanged, and exactly one daemon remained.

These desktop checks used one monitor and do not establish universal success across applications or every event ordering. The two-second limit bounds AX resolution, not the age of the link click. Same-application AX-only notifications retain the existing native-focus handling.

## PR review corrections

Both Greptile findings on PR #59 were reproduced with failing regression tests. A consumed click could acquire a new target from an unrelated later focus event. An activation echo matching an internal focus request could also borrow newer keyboard input or a click on another window to bypass suppression.

The correction removes consumed-click resurrection and the two-second release-correlation heuristic. Release correlation is scoped to the pending release snapshot again. Application activation no longer rebinds mouse intent; its separate, current activation token still admits legitimate external focus after the source click has been consumed.

A matching internal activation remains suppressed while its write is outstanding or has failed, unless newer pointer input explicitly identifies that same window. A click elsewhere cannot establish its external origin. External activations without a matching internal request do not require a recent click.

The follow-up review identified that successful requests also suppressed later Command-Tab activations for the remainder of the suppression deadline. Successful completion now records a monotonic timestamp instead of just a Boolean. A keyboard focus intent after that completion can supersede the suppression; input at or before completion cannot. The completion callback still checks the request ID, and superseded, cancelled-after-mutation, or failed requests do not gain a successful-completion timestamp. Direct pointer targeting is unchanged. Concurrent activation during an outstanding write remains conservative because its origin is ambiguous.

The regression first failed with `swift test --filter keyboardActivationAfterCompletedFocusIsNotConsumed`. It now covers keyboard input before, at, and after completion. Existing delayed-echo cases go through the completion helper, and direct-click coverage includes both outstanding and completed requests. A desktop integration test completes a real focus write, injects normalized keyboard and activation events, and verifies that real AX resolution preserves the activation in the resulting snapshot. This is not a physical Command-Tab test. Validation passed 753 unit tests and the new desktop test with Accessibility available; the desktop suite had 22 passes, one skip, and the pre-existing floating-window stacking failure.

Review-fix validation: `swift build` and 751 tests passed. Desktop tests with Accessibility available produced 20 passes, one skip, and one floating-window stacking failure. The same assertion and window-order values failed on the unmodified PR head `9c20e96` in an isolated checkout, so this failure predates the review corrections. The installed build passed verification with its signing requirement preserved. Computer Use confirmed a Finder link revealing Helium's workspace with `activation=true accepted=true mouseIntent=false keyboardIntent=false`. Automated Cmd-Tab produced no observable transition, so it does not count as a successful Cmd-Tab smoke test.
